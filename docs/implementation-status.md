# AudioPatch 原生实现进度

本轮交付是第一批原生代码，不是已完成的可安装成品。以仓库的需求、架构、详细设计和首次使用设计为基线。

## 已实现

- Stage 工程目录、EntryAbility、ArkUI 首页和编辑页面，compatible SDK 固定为 `6.0.0(20)`。
- 首页完整录制/导入入口、折叠的可选文字输入、空项目状态、恢复入口。
- 异步操作状态、进度、取消、30 秒超时、失败和重试；取消后丢弃过期结果，重录请求携带所选句段。
- 句段文字与范围修订、候选采用规则、恢复原音频的数据表达。
- 审核绑定文字/范围/策略版本、USER 和时间；实际导出入口检查审核（P1-FR-010）。
- 整数微秒时间轴，保留源音频的前缀、间隙和尾部，替换长度变化后顺延；无句段时仍保留完整源音频（P1-FR-014/020）。
- 预览/导出传递同一编译器生成的片段结构，替换素材淡入/淡出默认各 10 ms、最长半段（P1-FR-016—018）。目前只编译计划，不处理声音。

唯一未接入调用位置在 `infrastructure/HuaweiCapabilities.ts`。当前适配器仅作为第一批能力边界，接入时按能力拆为独立适配器。没有硬编码识别结果、虚假录音、网络回退或虚假保存成功。因为持久化尚未实现，当前不会显示“已保存”。

当前 30 秒超时是未接入能力的框架看门狗。正式录音、识别和导出接入时必须按操作区分超时，或使用无进展超时；不能用此固定值中断正常长录音。

## 环境与验证

- 本机未发现 DevEco Studio、HarmonyOS API 20 SDK 或 hvigor 可执行程序。
- 本机 `/Applications/harmony_app` 用于参考 Stage 工程结构，其 API 12 配置未复制到本项目。

- `tests/domain.test.mjs` 验证审核失效、时长顺延、源音频覆盖、过期候选拒绝、非法边界和空句段。
- `tests/typecheck.cjs` 通过本机 VS Code 的 TypeScript 检查平台无关层；这不等价于 ArkTS/ArkUI 编译。
- `tests/session.test.cjs` 使用仅存在于测试的注入端口，验证导出门槛、重录目标、挂起取消、迟到回调与超时。
- ArkTS 编译、HAP 签名、模拟器、实机、权限拒绝、飞行模式、重启恢复和音频质量均尚未验证。

## 打开工程

在支持 HarmonyOS 6.0.0 API 20 的 DevEco Studio 中打开仓库根目录，安装对应 SDK 并同步 hvigor/ohpm。为 `default` 产品配置自己的签名；不要提交证书或 `local.properties`。当前页面可供后续编译调试，媒体按钮会显示明确未接入状态。

领域测试：`node tests/domain.test.mjs`（Node 24）；类型检查：`node tests/typecheck.cjs`（检查器路径目前绑定此开发机）。
