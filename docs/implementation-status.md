# AudioPatch 原生实现进度

更新：2026-10-15。本轮接通完整录音的第一条真实设备链路并修复项目保存故障；目前可以在官方 API 20 模拟器录制有效 M4A、读取时长并写入项目修订，最新 HAP 已重新安装并启动，设备私有目录仍能恢复既有项目。设计基线为需求、架构、详细设计和首次使用设计，compatible 与 target SDK 固定为 `6.0.0(20)`。

## 已实现

- Stage 工程、EntryAbility、ArkUI 首页/编辑页；完整录音、音频选择器导入入口和折叠的可选文字输入，没有生产演示数据。
- 完整录音使用 Media Kit `AVRecorder`，在用户点击后申请 `ohos.permission.MICROPHONE`，支持开始、暂停、继续和结束。AAC 单声道音频封装为 M4A，写入应用私有 `filesDir/projects/<project>/assets`；结束后使用 `AVMetadataExtractor` 读取真实时长，只有有效时长和项目元数据提交都成功时才进入编辑页（P1-FR-002/019）。
- 录音取消、超时、权限拒绝和媒体错误不会制造项目。权限等待期间禁止重复启动；异常路径释放录音器和文件描述符，并删除未提交源文件。录音停止后先保留待提交资产身份，只有项目修订和 HEAD 提交成功才最终确认；提交失败会回滚 M4A 和空项目目录，避免留下孤立资产。已提交的源音频没有覆盖入口。
- 可移植开发检查：Node 24、pnpm 锁文件、固定开发依赖、GitHub Actions；移除 VS Code 绝对路径。配置检查覆盖 API 20、Stage、页面、字符串、离线权限、已跟踪证书和本地 SDK 配置。
- 官方 hvigor 包装器构建入口，支持 `HARMONY_HVIGORW` 和 `HARMONY_NODE`；缺工具链时明确退出 2，不生成占位 HAP。
- 句段编辑：改字、整数微秒边界、手动建段、拆分、合并相邻句段、采用兼容补录及恢复原音（P1-FR-009/013）。拆分/合并保留来源 ID 和候选历史，不自动采用旧范围的补录。
- 编辑在副本上执行，持久提交成功后才发布；保存失败保留之前的项目和草稿。文字编辑说明不改变声音；范围字段按源音频秒数输入，拒绝超六位小数、非法范围和重叠。
- 修订存储算法：追加不可变修订、schema 校验、意外损坏校验和、预期 sequence 冲突检测、HEAD 原子替换、提交凭据恢复、孤立修订隔离、源资产 ID/时长不可变（P1-FR-019/020/021）。一处损坏项目不会隐藏其他有效项目。
- API 20 模拟器首次真实保存暴露出 Core File Kit `mkdirSync(path, true)` 在目标目录已存在时返回 `13900015 (File exists)`：修订已移动到 `revisions`，再次写 HEAD 时因复用 `staging` 中断。设备适配器现仅将该错误视为父目录已经就绪，其他 I/O 错误仍向上抛出；回归测试覆盖同一事务复用父目录（P1-FR-019/020）。
- 当前会话内撤销编辑、识别与补录提交；撤销创建新修订，sequence 单调增加。保存失败不消费撤销历史，撤销后页面输入重新同步已保存内容。
- 项目列表加载与打开从 ProjectStore 读取；启动加载失败明确提示，不能以读取失败显示“没有项目”。恢复不增加修订。
- 首页项目管理已支持二次确认删除；删除通过 Core File Kit 递归移除项目目录，包含源录音、修订、receipt、staging 和编辑记录；删除失败保留原项目（P1-NFR-004）。
- 原音范围试听与候选试听使用独立 manifest；API 20 已接入 Media Kit `AVPlayer` 私有 FD 播放，只有收到完整范围的 `timeUpdate`/`completed` 事件才返回成功，播放器错误、取消和资源缺失返回失败并释放播放器。候选试听不会更改采用版本。只有完整源范围播放成功后才能确认边界；修改后凭据失效。导出入口进入“检查并确认”，实际导出仍执行审核硬门槛（P1-FR-010）。
- 时间轴保留完整源覆盖，替换长度变化后顺延；预览/导出共用编译计划，淡入淡出默认 10ms、最长半段（P1-FR-014/016—018）。目前只编译计划，不处理声音。
- 异步进度、取消、超时及迟到结果隔离。适配器接收 detached project，失败时不能原地污染当前项目。HEAD 提交阶段不能冒充已取消；提交凭据写入失败返回已提交并提示恢复风险。

## 事务实现的边界

- `schemaVersion=1` 为第一版代码内核格式；此前未在设备生成有效持久化数据，不迁移设计文档里的示例 JSON。未来需显式 schema 迁移。
- 一个应用持有一个 ProjectStore，队列串行写入；不支持跨进程或多个 store 对同一目录并发写入。
- HEAD 原子替换是提交点。随后 receipt 失败时，HEAD 仍有效，向用户提示恢复覆盖不足；若此后 HEAD 也损坏而没有有效凭据，拒绝将该项目当作新项目覆盖。
- 当前校验和仅发现意外文本损坏，尚非密码学 stateHash；资产哈希、真实音频引用存在性、持久化 undo 栈、启动时孤立文件回收仍待实现。撤销范围目前只覆盖当前会话。
- 录音文件在开始时写入项目目录，结束后先保留待提交身份；元数据读取或项目提交失败都会删除当前 M4A 和空目录，项目提交成功后才清除待提交身份。启动时跨进程遗留资产回收仍待实现。
- 固定 30 秒只约束开始、暂停、继续和结束等命令调用，不限制录音持续时长。正式识别和导出接入前必须改为每操作时限或无进展超时。
